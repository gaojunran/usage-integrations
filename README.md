# commander-usage

Generates [usage spec](https://usage.jdx.dev) for CLIs written with [Commander.js](https://github.com/tj/commander.js).

## Install

```sh
npm install commander-usage
```

## Usage

```js
const { Command } = require("commander");
const { generate } = require("commander-usage");

const program = new Command("mycli")
  .version("1.0.0")
  .description("My CLI tool")
  .option("-v, --verbose", "Enable verbose output")
  .option("-f, --file <FILE>", "Input file")
  .option("--no-color", "Disable colored output");

const sub = program.command("run").description("Run a task");
sub.command("start").description("Start the task");
sub.command("stop").description("Stop the task");

// Generate usage spec as KDL
console.log(generate(program));
```

Output:

```kdl
// @generated by commander-usage from Commander.js metadata
name mycli
bin mycli
version "1.0.0"
about "My CLI tool"
flag "-v --verbose" help="Enable verbose output"
flag "-f --file" help="Input file" {
    arg <FILE>
}
flag --no-color help="Disable colored output" negate=--color
cmd run help="Run a task" subcommand_required=#true {
    cmd start help="Start the task"
    cmd stop help="Stop the task"
}
```

## Integration with `usage` CLI

The recommended pattern is to add a `--usage-spec` flag that outputs the spec, then pipe it to the `usage` CLI for completions, docs, and man pages:

```js
const { Command } = require("commander");
const { generateToStdout } = require("commander-usage");

const program = new Command("mycli")
  .option("--usage-spec", "Generate usage spec");

// Before parsing, check for --usage-spec
if (process.argv.includes("--usage-spec")) {
  generateToStdout(program);
  process.exit(0);
}

program.parse();
```

Then use it with the `usage` CLI:

```sh
mycli --usage-spec | usage generate completion bash
mycli --usage-spec | usage generate md -f -
mycli --usage-spec | usage generate man -f -
```

## API

### `generate(cmd, binName?)`

Generates a usage spec in KDL format from a Commander.js `Command`.

- `cmd` - A `Command` instance from Commander.js
- `binName` - Optional binary name override (defaults to `cmd.name()`)
- Returns: KDL string

### `generateJSON(cmd, binName?)`

Generates a usage spec in JSON format from a Commander.js `Command`.

- `cmd` - A `Command` instance from Commander.js
- `binName` - Optional binary name override
- Returns: JSON string

### `generateToStdout(cmd, binName?)`

Writes the KDL spec to stdout. Useful for piping to the `usage` CLI.

### `convertRoot(cmd)`

Converts a Commander.js `Command` to the internal `Spec` data structure. Useful if you need to inspect or transform the spec before rendering.

### `renderKDL(spec)`

Renders a `Spec` object as KDL.

## Supported Features

| Commander.js Feature | Usage Spec Mapping |
|---|---|
| `cmd.name()` | `name` / `bin` |
| `cmd.version()` | `version` |
| `cmd.description()` / `cmd.summary()` | `about` / `long_about` |
| `cmd.option()` | `flag` |
| `cmd.requiredOption()` | `flag required=#true` |
| `cmd.argument()` | `arg` |
| `cmd.alias()` | `alias` |
| `cmd._hidden` | `hide=#true` |
| `opt.hideHelp()` | `hide=#true` |
| `opt.env()` | `env` |
| `opt.choices()` | `choices` |
| `opt.defaultValue` | `default` |
| `--no-*` options | `negate` |
| Subcommands | `cmd` (recursive) |
| Non-runnable subcommand groups | `subcommand_required=#true` |
| `arg.choices()` | `choices` |
| `arg.defaultValue` | `default` |
| Variadic arguments | `var=#true` + ellipsis |
